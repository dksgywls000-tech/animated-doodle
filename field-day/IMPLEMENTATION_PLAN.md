# 구현 계획 — 2026 하이테크본부 가을운동회 모바일 웹앱

## 0. 저장소 확인 결과
- 기존 저장소에는 단일 HTML(`insta-tag-2026-08-01.html`)만 있고 서버·DB·빌드 체계가 없다.
- 기존 파일은 건드리지 않고 `field-day/` 하위에 독립 앱을 만든다.
- 기술: Node 22 + TypeScript, Fastify 5(API·정적 파일), `ws`(WebSocket), PostgreSQL 16(`pg`), React 19 + Vite(SPA, 같은 오리진에서 서빙), Vitest(실 DB 통합 테스트), Playwright(E2E·반응형 스크린샷).
- 유료 서비스·외부 SaaS 의존 없음. 외부 배포·QR 생성은 하지 않는다.

## 1. 권한
| 역할 | 할 수 있는 것 |
|---|---|
| participant | 본인 정보·행운권·자기 조·공개 안내·전체 채팅·자기 조 채팅·도움 요청(본인 것만 조회) |
| admin | participant + 점수판·부여·취소·로그·내보내기, 공지/일정/경기설명/진행상태 관리, 신고·숨김, 도움 요청 처리, 체크인 현황, 감사 기록이 남는 타 조 채팅 열람 |
| owner | admin + 명단 CSV 업로드, 관리자 지정/해제, 체크인 후 조 예외 변경, 행사 설정, 명단·체크인·감사 내보내기 |

- 역할·조·활성 여부는 **매 요청마다 DB에서 다시 읽는다**(세션에는 participant_id만). 클라이언트가 보내는 role/team_id는 어디에서도 사용하지 않는다.
- WebSocket은 업그레이드 시 쿠키 세션 검증, 구독 시 권한 검증, **전송 직전 DB 재검증**(점수·팀채팅). 역할/조 변경 시 `revalidate` 신호로 해당 사용자의 구독을 즉시 끊는다.
- 참가자용 응답 타입에는 score/rank/history 필드가 아예 없다. 점수 데이터는 `/api/admin/*`에서만 읽힌다.

## 2. 행운권(체크인) 알고리즘
1. 행사 초기화 시 `crypto.randomInt` Fisher–Yates로 1~300을 섞어 `ticket_pool(position→number)`에 저장.
2. 최초 로그인 성공 시 트랜잭션:
   `allocation_state` 행 `FOR UPDATE` 잠금 → 기존 체크인 재확인(있으면 그대로 반환) → `seq = next_sequence` →
   `seq ≤ 300`이면 `ticket_pool[seq]`, 아니면 `seq` → `checkins` INSERT → `next_sequence+1` → COMMIT.
3. 제약: `UNIQUE(event_id, participant_id)`, `UNIQUE(event_id, checkin_sequence)`, `UNIQUE(event_id, ticket_number)`.
4. 어떤 단계가 실패해도 전체 롤백 → 카운터도 증가하지 않는다. 재시도·다중 기기 로그인은 기존 행을 반환.
5. 로그아웃·비활성화·명단 재업로드는 `checkins`를 건드리지 않는다. 행운권 리셋 UI는 없다.

## 3. 점수 원장
- `score_awards`(불변) + `score_reversals`(`UNIQUE(award_id)`, points = -원점수). UPDATE/DELETE를 막는 DB 트리거.
- 합계 = Σ awards − Σ reversals. 캐시 합계 없음(8개 조 × 수백 행이라 즉시 계산).
- 부여: 정수 10~200, 10의 배수(DB CHECK + 서버 검증). `idempotency_key` 유일 → 재전송은 원래 결과 반환.
  같은 관리자·조·종목·점수·사유가 60초 내 반복되면 `409 duplicate_warning`, 사용자가 명시 확인 시 별도 부여.
- 취소: 관리자 세션 + 서버 해시(scrypt) 비밀번호(기본 1234, 환경변수로 변경). 원기록 `FOR UPDATE` 잠금 후 reversal INSERT, `UNIQUE(award_id)`로 동시 취소도 1회만. 틀린 비밀번호는 관리자별 시도 제한, 로그에 비밀번호 미기록.

## 5. 원문 미확정 사항 처리
- 14:30 공 튕기기 시작 시각, 튜브릴레이 3위 결정 방식 → 일정은 `시간 확인 중` 상태로, 경기설명은 `확정 전` 표기로 시드. 관리자 화면 `초기 설정 체크리스트`에 남김.

- 원문 배점(200/100/50)은 참가자 화면에 표시하지 않으며 자동 채점하지 않는다.
