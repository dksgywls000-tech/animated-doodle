## 통합 테스트(실 DB)에서 검증한 항목
**로그인·행운권** (`tests/login-ticket.test.ts`)
- 올바른 쌍 통과 / 잘못된 쌍·미등록·비활성 같은 문구로 거절 / 다른 행 이름+사번 혼합 거절 / 동명이인 각자 연결
- `000123` 앞자리 0 보존(`123` 거절), 앞뒤 공백 제거·내부 공백 유지·NFC 정규화
- 같은 IP+계정 5회 실패 후 429, 다른 IP의 정상 사용자는 영향 없음
- **350명 동시 HTTP 로그인**: 순번 1~350 연속, 번호 유일, 1~300순번은 정확히 {1..300}의 셔플, 301번째=301·350번째=350
- 동일인 10개 동시 요청 → 체크인 1개, 순번 구멍 없음
- 번호 확보 후 저장 전 강제 실패 → 체크인·카운터 롤백, 재시도 시 같은 순번으로 정상 배정, 응답 유실 재시도는 같은 번호
- 299/300/301 경계 동시 요청 → 남은 풀 번호 2개 + 301
- 재로그인·다중 기기·로그아웃·비활성화 후 재활성·명단 재업로드에도 번호 유지
- 참가자 API 어디에도 풀/순번 정보 없음

**권한·점수** (`tests/scores-auth.test.ts`)
- participant가 관리자·owner API 11개 호출 → 403, 점수 바이트 없음 / 비로그인 401 / admin의 owner API 403
- 쿠키·헤더·로그인 본문에 role/team을 넣어도 무시
- 참가자 공개 API 7개에 score/total/rank/points/history·배점 문구 없음
- CSRF 토큰 없음·외부 Origin 변경 요청 거절
- 200+50=250, 50 취소 후 200 / 비밀번호 오류 시 합계 불변·감사 로그에 비밀번호 없음 / 참가자는 1234로도 취소 불가
- 비밀번호 5회 오류 후 429(맞는 비밀번호도 제한 중 거절)
- 15·0·-10·201·210·"100"·10.5·null 거절, DB CHECK도 동일
- 이벤트 세부유형·구체 사유 필수, 공백 사유 거절
- 같은 idempotency key 5개 동시 → 1회 반영
- 60초 내 동일 내용 → 409 경고, 명시 확인 시 별도 부여
- 두 관리자 20건 동시 부여 → 모두 정확히 반영
- 같은 기록 5개 세션 동시 취소 → 1회만 상쇄, 재취소 409 / 서비스 직접 20개 동시 취소 → reversal 1개
- 원장 UPDATE/DELETE는 DB 트리거가 거부
- 새 앱 인스턴스·새 커넥션 풀(재시작 흉내)에서 동일 합계, 원장 재계산과 일치, 원부여자·취소자 구분
- 공동 순위, CSV BOM·수식 주입 방지
- 관리자 해제 → 기존 세션으로 관리자 API 즉시 403, 자기 강등 금지

**채팅·실시간** (`tests/chat-realtime.test.ts`)
- 타 조 채팅 HTTP 조회·작성 403, 다른 조 메시지 신고 경로로도 열람 불가
- 채팅 응답에 사번 없음 / XSS 문자열은 텍스트 그대로(JSON) / 빈 내용·501자 거절 / 같은 clientMsgId 5개 동시 → 1건 / 도배 6번째 429
- 삭제 표시 유지, 남의 메시지 삭제 불가, 관리자 숨김·신고 목록
- 관리자 타 조 열람은 별도 경로 + 감사 기록 / 미읽음·읽음 / 잘못된 커서 400
- WebSocket: 비로그인·외부 Origin 거절, 참가자의 admin·타 조 구독 거절
- 참가자·관리자·타 조 3개 실제 소켓: 점수 이벤트는 관리자만, 조 메시지는 해당 조만
- 관리자 해제 → admin 구독 즉시 revoked, 이후 점수 이벤트 미수신 / DB 직접 변경도 다음 전송 때 재검증 차단
- 조 변경 → 이전 조 구독 해제·HTTP 403·새 조 연결, 감사 기록(이전/이후 조·사유)
- 로그아웃 → 해당 소켓 session_ended 후 종료

**명단·콘텐츠** (`tests/roster-content.test.ts`)
- CSV: BOM·CRLF·따옴표·한글 헤더·`3조` 표기 / 조 범위·역할·활성·빈값·중복·대소문자 중복 오류 행 번호 / 동명이인 허용
- owner만 업로드, 오류 시 전체 중단, 역할 변경 별도 확인, 자기 강등·비활성·마지막 owner 보호
- 체크인 후 조 변경 업로드 거절, 재업로드 후 행운권 유지, 업로드 비활성화 시 세션 종료
- admin은 사번 마스킹, owner 내보내기는 전체
- 공지 읽음, 일정 초안·‘시간 확인 중’, 배점 미노출, 주차 공개 전 null, 수동 ‘진행 중’ 우선
- 도움 요청 본인만 조회·재전송 중복 없음·상태 반영 / 체크리스트 항목 / DB·파서 원문 오류 미노출
- 현재/다음 계산: 행사 당일 시각 추정, 행사 전, 행사 후(잠기지 않음)

## E2E (Chromium, 실제 서버)에서 확인한 항목
1. 잘못된 이름·사번/비활성 계정 일반 문구
2. 참가자 조·행운권 표시, 새로고침 후 번호 동일, 관리자 버튼·점수 없음, `#/admin` 직접 접근 시 권한 없음 화면, `000123` 로그인
3. **두 관리자 + 참가자 3세션**: 휠을 키보드로 조작해 3조 +100 → 확인 단계 → 부여 → 다른 관리자 점수판 실시간 갱신, 이벤트(제기차기) 부여, 틀린 비밀번호 차감 없음 → 맞는 비밀번호로 취소 → 표에 ‘취소됨’·취소자 표시 → 합계 복귀. 참가자 소켓 프레임에 점수 관련 데이터 0
4. 전체 채팅 실시간(XSS 문자열은 텍스트로 표시), 3조 팀 메시지가 같은 조에는 보이고 5조에는 안 보임
5. 오프라인 배너 표시·복귀
6. 360/390/430/768/1440 너비: 5개 화면 가로 스크롤 없음, 관리자 CTA가 탭바와 겹치지 않음, 버튼·탭 높이 ≥ 40px (주요 버튼 48px)
7. 지도 확대 보기 열기·확대·닫기
8. `10_staff_schedule` 404, JS 번들에 비밀번호 해시·명단 사번 없음, `/api/*` no-store

## 검증하지 못한 것 / 알려진 미완료
- **Firebase 실제 프로젝트(클라우드)에는 배포해 보지 않았습니다.** 에뮬레이터 기준 검증이며, 실제 배포 시 서비스 계정 권한(안내서 3-4단계)과 인덱스 생성이 필요합니다.
- **실제 iPhone Safari·Android Chrome 기기 테스트는 하지 못했습니다.** Chromium 모바일 뷰포트로만 확인했습니다. iOS 키보드에 대한 입력창 처리(visualViewport 기반)는 실기기 확인이 필요합니다.
- 실제 300~400명 규모 **네트워크 부하 테스트**(실제 다수 기기·행사장 Wi-Fi)는 하지 않았습니다. DB 동시성은 350 동시 로그인으로 검증했습니다.
- 지도의 ‘내 조 자리’·화장실·보건실 강조 원은 원본 배치도 인쇄 위치를 눈으로 맞춘 좌표입니다(GPS 아님). 현장 배치가 바뀌면 `client/src/util.ts`의 좌표를 수정해야 합니다.
- 행운권 추첨·경품 관리, 여러 조 일괄 점수 부여, 파일 첨부 채팅은 범위 밖으로 구현하지 않았습니다.
- 원문 미확정 사항(14:30 중복, 튜브릴레이 3위, 동률 기준, 귀가 배차 등)은 운영진 확정이 필요합니다. 앱에서는 ‘초안’/‘시간 확인 중’/‘확정 전’으로 표시됩니다.
- 외부 배포·QR 제작은 요청대로 하지 않았습니다.
