# 운영자 매뉴얼

## 0. 역할
| 역할 | 할 수 있는 일 |
|---|---|
| 참가자 | 내 조·행운권, 일정·지도, 전체 채팅·우리 조 채팅, 도움 요청 |
| 관리자(admin) | + 점수판·부여·취소·기록·CSV, 공지·일정·경기설명·교통 안내, 도움 요청·채팅 신고 처리, 체크인 현황 |
| owner | + 명단 업로드, 관리자 지정/해제, 체크인 후 조 예외 변경, 명단·감사 내보내기 |

관리자도 명단에 있는 참가자이며, 로그인하면 참가자와 똑같이 행운권을 받습니다. 하단 **관리자 화면** 버튼은 서버가 관리자로 확인한 계정에만 보입니다.

> **인증 한계** 이름+사번 입장은 행사용 간편 확인이며 강한 본인 인증이 아닙니다. 다른 사람의 이름·사번을 아는 사람은 그 사람으로 입장할 수 있습니다. 관리자 사번은 외부에 공유하지 마세요.

## 1. 최초 준비 순서
1. `.env` 설정 (`APP_MODE=production`, `DATABASE_URL`, `RATE_LIMIT_SECRET`, 필요 시 `SCORE_CANCEL_PASSWORD_HASH`).
2. `npm run cli -- init-event` — DB 마이그레이션, 1~8조, 행운권 1~300 셔플 풀(보안 난수) 생성. 여러 번 실행해도 기존 데이터는 바뀌지 않습니다.
3. **실제 명단 CSV**를 서버에서 가져오기: `npm run cli -- import-roster roster.csv --confirm-role-changes`
   - owner 행은 `role=owner`로 넣거나, 별도로 `npm run cli -- add-owner --employee-id <사번> --name <이름> --team <조>` 또는 환경변수 `BOOTSTRAP_OWNER_EMPLOYEE_IDS`로 지정합니다.
   - 클라이언트 화면에서 관리자 역할을 만들 방법은 없습니다.
4. owner로 로그인 → 관리자 화면 → **공지·일정** 탭의 **초기 설정 체크리스트**를 확인합니다.
5. 배포 후 URL로 QR을 직접 만듭니다(앱은 QR을 만들지 않음).

실제 명단 CSV는 Git에 커밋하지 마세요(`.gitignore`에 `roster*.csv` 제외 규칙 있음).

## 2. 명단 CSV
```
employee_id,name,team_number,role,active
000123,홍길동,3,participant,true
```
- 한글 헤더(`사번,이름,조,역할,활성`)도 됩니다. UTF-8(BOM 포함)·Excel 기본 CSV(CP949) 모두 읽습니다.
- 사번은 문자열 그대로 저장합니다(앞자리 0 보존, **대소문자 구분 정확 일치**). 대소문자만 다른 사번은 오류로 막습니다.
- `role` 비우면 participant, `active` 비우면 true. 조는 1~8(`3조`도 허용).
- 동명이인 허용, 사번 중복 불가.
- **병합 정책**: 사번 기준. 새 사번 추가, 기존 사번은 이름·활성·역할 갱신. **파일에 없는 기존 사람은 그대로 유지**(삭제 없음). 빼려면 `active=false`.
- 오류 행이 하나라도 있으면 전체 반영을 중단합니다(행 번호·이유 표시).
- 역할 변경이 있으면 미리보기에서 확인 체크 후에만 반영됩니다.
- 체크인한 사람의 조는 업로드로 바꿀 수 없습니다 → owner 화면 **조 변경**(사유 필수, 감사 기록, 이전 조 채팅 즉시 차단).
- 본인 강등·본인 비활성화·마지막 owner 제거는 막혀 있습니다.
- 재업로드해도 체크인·행운권·점수·채팅 기록은 바뀌지 않습니다. 비활성화된 사람은 즉시 로그아웃됩니다.

## 3. 행운권 번호 정책
- 번호는 **최초 로그인 성공 순서**로 정해집니다(명단 순서·사번·조와 무관).
- 1~300번째 입장자: 아직 안 쓰인 1~300 중 무작위 번호(서버 셔플 풀).
- 301번째부터: 입장 순번 그대로(301, 302, …).
- 재로그인·새로고침·여러 기기 로그인·비활성화·재업로드에도 번호는 바뀌거나 재사용되지 않습니다.
- 앱에는 번호 리셋/전체 삭제 버튼이 없습니다. 추첨은 이번 범위가 아니며, 명단·체크인 CSV(owner)에 번호가 들어 있습니다.

## 4. 점수 부여
관리자 화면 → 조 카드 클릭(또는 **점수 부여**) → 종목 → 점수(빠른 칩 200/100/50/40/30/20/10 또는 휠 10~200, 10점 단위) → 사유 → **최종 확인** → `N조에 X점 부여`.
- 이벤트는 세부 유형(풍선 빨리 터트리기·이벤트 줄넘기·제기차기·이벤트 튜브릴레이·기타) 선택과 구체 사유가 필수, 응원점수도 구체 사유 필수.
- 앱은 원문 배점(200/100/50)으로 자동 채점하지 않습니다. 모두 수동 입력입니다.
- 풍선기둥 연합팀은 각 조에 같은 점수를 **조별로 각각** 부여합니다.
- 같은 내용을 60초 안에 다시 부여하면 경고가 뜨고, 확인하면 별도로 부여됩니다.
- 네트워크가 끊겨 결과를 모르면 앱이 자동으로 다시 보내지 않습니다. **결과 확인 후 재시도**는 같은 요청 ID로 보내 중복 반영되지 않습니다.
- 참가자 화면·API·실시간 채널에는 점수·순위가 전혀 전달되지 않습니다. 채팅에 직접 점수를 쓰는 것은 시스템이 막을 수 없으니 운영진끼리 주의해 주세요.

## 5. 점수 취소
**점수 기록** → 해당 행 **취소** → 취소 사유 + 취소 비밀번호.
- 원기록은 지워지지 않고 정확히 같은 크기의 음수 상쇄 기록이 붙습니다. 취소자·시각·사유가 남습니다.
- 다른 관리자의 기록도 취소할 수 있습니다. 한 기록은 한 번만 취소됩니다(동시에 눌러도 1회).
- 취소를 되돌리는 기능은 없습니다. 필요하면 새로 부여하세요. 사유 수정도 불가(취소 후 새 부여).
- 비밀번호를 10분 안에 5번 틀리면 그 관리자는 10분간 취소가 제한됩니다.

### 취소 비밀번호 바꾸기
기본값은 `1234`입니다. 서버에서:
```bash
npm run hash-password        # 새 비밀번호 입력 → SCORE_CANCEL_PASSWORD_HASH='scrypt$...' 출력
```
출력값을 서버 환경변수에 넣고 재시작합니다. 비밀번호 원문은 어디에도 저장·전송·기록되지 않습니다.

## 6. 공지·일정·안내
**공지·일정** 탭:
- **진행 상태 안내**: 참가자 화면 상단 문구(예: “공 튕기기 14:40 시작”).
- **일정 확정 공개**: 끄면 참가자에게 ‘초안’으로 보입니다(초기값 꺼짐).
- **일정·진행 상태**: 각 순서를 예정/시간 확인 중/진행 중/종료/지연으로 바꿉니다. ‘진행 중’은 운영진이 지정한 것이 최우선이며, 지정이 없으면 행사 당일 한국시간 예정 시각으로 ‘지금’을 추정 표시합니다. 기기 시각으로 상태를 자동 확정하지 않습니다.
- **공개용 경기 설명**: 인원·방법·대진 안내 수정. ‘확정 전 안내’를 비우면 확정 표시가 사라집니다.
- **교통·주차**: 주차 안내(원문: 3시간 무료·초과 개인 부담)는 확인 후 공개 체크. 귀가 버스는 확정 정보를 입력하고 공개 체크.

원문 미확정 사항(체크리스트): 14:30 이벤트 줄넘기↔공 튕기기 중복, 튜브릴레이 3위 결정 방식, 경기별 동률·교체·실패 기준, 제기차기 배점 해석, 귀가 배차.

## 7. 채팅·도움 요청
- 참가자는 전체 방과 자기 조 방만 읽고 씁니다. 다른 조 방 열람은 관리자 API(감사 기록)로만 가능합니다.
- 채팅에서 관리자는 **숨기기**, 참가자는 **신고**. 신고는 **요청·신고** 탭에서 처리합니다.
- 도움 요청(길 안내/물품/기타)은 **요청·신고** 탭에서 상태를 바꾸면 요청자 화면에 반영됩니다. 앱은 상시 실시간 대응을 약속하지 않으며, 응급 상황은 운영지원·응급보건실로 직접 오도록 안내합니다.

## 8. 백업·종료 후 삭제
- 행사 전·중간·종료 직후 백업: `pg_dump -Fc "$DATABASE_URL" > fieldday-$(date +%Y%m%d-%H%M).dump`
- 복구: `pg_restore --clean -d "$DATABASE_URL" <파일>` (의도적인 운영 절차로만, 앱에는 초기화 버튼 없음)
- CSV 내보내기: owner 화면(명단·체크인·행운권 / 점수 기록 / 감사 기록). 개인정보가 포함되니 보관 위치를 제한하세요.
- **종료 후 권장 정책**: 시상·정산 확인 후(예: 2주 이내) 최종 백업 1부만 지정 담당자가 보관하고, 운영 DB와 서버를 삭제합니다. 채팅 원문·사번이 포함된 백업은 보관 기한이 지나면 파기합니다.
